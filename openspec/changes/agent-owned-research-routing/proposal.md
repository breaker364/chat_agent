## 为什么需要

当前的受控研究设计会把 `knowledge_search`、工作区和联网证据工具从主 Agent 的工具列表中移除，改由一个隐藏的 coordinator 在 Agent 回答前执行。这会导致 Agent 认为已注册的工具不存在，研究失败时也无法在会话中追踪原因，甚至可能绕过检索流程，直接读取内部索引文件。

来源选择应该仍由 Agent 决定，并且应当出现在正常的工具调用记录中。对于语义不明确的问题，二级规划步骤仍然有价值，但它应该辅助 Agent，而不是取代 Agent 选择和调用合规只读工具的能力。

## 变更内容

- 当工具已注册且功能启用时，将 `knowledge_search`、工作区只读工具和联网搜索/抓取工具暴露给主 ReAct Agent。
- 将 `ModelResearchPlanner` 暴露为只读 Agent 工具，返回经过 schema 校验且有边界的来源建议；该工具本身不执行证据检索。
- 建立由 Agent 负责的路由流程：Agent 先判断能否直接回答；需要证据且用户未明确指定来源时，调用 planner 工具，然后自行选择并调用合规的证据工具。
- 用户明确要求知识库或联网搜索时，优先执行用户选择，跳过 planner，直接调用相应的已暴露证据工具。
- 在工具边界执行来源策略和调用预算；禁止规划结果、提示词或回退逻辑直接读取 `knowledge_base/index` 或其他内部索引文件来替代检索。
- 在会话和流式事件中持久化有边界的路由决策与证据工具结果，记录规划失败或检索失败的具体类别，但不保存模型推理过程或原始证据正文。

## 能力范围

### 新增能力

- `agent-owned-research-routing`：允许主 Agent 在直接回答和证据检索之间进行选择；对不明确的请求使用有边界的二级规划；遵守用户明确指定的来源；提供可审计的路由结果。

### 修改能力

- 无。

## 影响范围

- 后端：`backend/agent.py`、`backend/agentic_research/*`、`backend/tools.py`、`backend/main.py`、会话事件持久化、提示词和运行时配置。
- 行为：证据工具出现在主 Agent 的工具 schema 中；用户明确要求知识库或联网搜索时，直接执行相应工具，不再隐式进行前置路由；自动请求使用 planner 作为二级判断。
- 测试：工具暴露、显式来源优先级、planner 工具校验、直接回答、策略与预算执行、会话可观测性，以及内部索引绕过防护。
