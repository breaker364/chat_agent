## 背景

当前前端为单文件 React 应用(`frontend/src/App.jsx` 约 3400 行)加全局样式(`App.css` 约 3100 行)。视觉上已有一套 "Soft Horizon" 浅色主题设计令牌(背景层级、边框、强调色、圆角、阴影、过渡),Google Fonts 已加载 Inter/Plus Jakarta Sans/JetBrains Mono,整体质感尚可。但逐条对照业界 AI 对话产品(ChatGPT、Claude、Perplexity、AWS Cloudscape Gen-AI 模式)可确认以下缺口:

1. **主题**:`App.css` 无暗色令牌,`prefers-color-scheme` 未使用,用户在暗环境使用刺眼。
2. **消息操作**:业界事实标准是助手消息 hover 出现"复制/重新生成/点赞点踩",用户消息可编辑;本项目完全没有。错误回复只是一段 `Request failed: ...` 文本。
3. **原生对话框**:重命名用 `window.prompt`、删除用 `window.confirm`,与应用内已有的 `FeishuImportDialog`、`KnowledgeCenter` 对话框质感割裂,且原生弹窗不可定制、阻塞主线程、移动端体验差。
4. **空状态**:新会话只有一条英文默认助手消息("Chat Agent is ready..."),而 ChatGPT/Claude 类产品把空状态做成了能力引导首屏。
5. **状态真实性**:`ToolCallBubble` 状态文本硬编码 "running";工具调用与结果有 `name` 配对信息却未利用。
6. **硬编码实体**:头部徽标字面量 "12306";`iconForTool` 用 "train"/"ticket"/"station" 关键词选择火车图标。按 AGENTS.md 规则 1/3,这类实体耦合应在本次一并泛化。

参考的公开实践:Smashing Magazine《Design Patterns For AI Interfaces》《Designing For Agentic AI》(渐进披露、可恢复操作)、LukeW《Showing the Work of Agents in UI》(工具活动作为进度指示、默认折叠、结果到达后收敛)、Setproduct《AI chat interface anatomy》(逐消息操作与布局解剖)、AWS Cloudscape Generative AI chat 模式(上下文操作与反馈)、OpenAI 社区案例(反馈与重新生成解耦,避免点踩触发重发)、shadcn/ai-chat 区块(空状态建议卡片)。

## 目标与非目标

**目标:**

- 在既有令牌体系上以最小成本支持浅色/暗色/跟随系统三档主题,切换无闪烁,暗色下满足 WCAG AA 对比度。
- 补齐业界标准消息级操作:复制、重新生成、编辑回填、反馈,以及相对时间、工具真实状态、错误重试、回到底部。
- 用应用内对话框统一替代原生 `prompt`/`confirm`,并沉淀可复用的对话框原语。
- 空状态提供能力引导与建议提示词,全部为通用能力描述,支持配置驱动。
- 消除界面层硬编码实体(徽标、图标关键词),满足 AGENTS.md 泛化性要求。

**非目标:**

- 不迁移 UI 组件库(如 shadcn/ui、Ant Design),不改变现有技术栈与依赖结构。
- 不做消息列表虚拟化(当前会话规模未触及性能瓶颈)。
- 不引入 i18n 框架,不做多语言切换;仅将主要界面文案与 `lang="zh-CN"` 对齐为中文。
- 不修改 SSE 事件契约、后端会话存储与知识库 API;后端仅可选新增一个最小反馈端点。
- 不实现消息级永久链接、分享卡片等文档化功能(UX Collective 对此类模式的批评保留为后续议题)。

## 决策

### 1. 主题切换用 `data-theme` 属性 + 令牌扩展,不用 CSS-in-JS 或多份样式

现有样式已通过 `:root` CSS 自定义属性组织,最小改动路径是:审查并令牌化剩余硬编码颜色,然后增加 `[data-theme="dark"]` 覆盖同一组令牌。三档选项(浅色/暗色/跟随系统)持久化到 localStorage,"跟随系统"用 `matchMedia('(prefers-color-scheme: dark)')` 监听。为避免首屏闪烁,在 `index.html` 的 `<head>` 内放一小段阻塞脚本,依据存储值或系统偏好在 `#root` 渲染前设置 `data-theme`。

备选方案是引入主题库(如 next-themes 类似物)或双份样式表。前者为单页应用增加不必要依赖,后者会导致两套样式漂移,均不采纳。

### 2. 消息操作走前端能力边界,重新生成不改历史

- **复制**:优先 Clipboard API,失败降级为 `execCommand`,成功后用 toast 确认(而非改变按钮语义)。
- **重新生成**:仅对最后一条助手消息提供,行为是取其对应最后一条用户消息,经现有 `/chat/stream` 重发;不删除、不改写历史消息,新回复正常追加,避免引入任何后端会话编辑语义。
- **编辑回填**:用户消息的"编辑"仅把内容(含附件说明文本中的正文部分)回填到输入框由用户修改后重新发送,不做破坏式历史改写。这与 ChatGPT 的就地编辑有差距,但不依赖后端变更,可作为第一阶段;后续如后端支持消息截断再升级。
- **点赞点踩**:独立按钮,点击即记录,不触发任何重发(吸取 OpenAI 社区"点踩自动重新生成扣额度"的反面案例);反馈先写本地(按 session/message 维度),后端最小 `POST /feedback` 端点就绪后切换为上报,失败静默降级回本地。

### 3. 工具气泡状态用配对推导,保持默认折叠

流式期间 `tool_call` 事件入列即显示运行中(转圈),其后同名 `tool_result` 到达时将其前未配对的最近同名调用标记为完成(结果含 `error`/异常特征时标失败),历史消息里同一 `tools` 数组天然可配对。这与 LukeW 总结的渐进披露一致:默认折叠为单行摘要,展开才看细节;避免把每次工具往返都摊开成"始终展开的时间线"。

### 4. 抽取通用 Dialog 原语,替换原生弹窗

从 `FeishuImportDialog` 的交互(遮罩点击关闭、Esc 关闭、加载中禁关闭)中抽取 `Dialog`/`ConfirmDialog`/`PromptDialog` 三个轻量原语:焦点圈闭(focus trap)、`role="dialog"` + `aria-modal`、打开时聚焦首个可交互元素。重命名会话改为 `PromptDialog`,删除会话改为 `ConfirmDialog`,后续知识库删除等也可复用。不引入第三方对话框库。

### 5. 空状态建议词走通用能力 + 配置驱动

空状态组件展示 3-4 张能力卡片(联网检索、文件分析、知识库问答、技能执行等通用能力)与若干建议提示词。建议词来自一份可被 `runtime_config.json` 或等价配置覆盖的通用默认列表,并动态追加已安装技能的使用示例(基于 `/skills` 返回的 `name`/`description` 生成)。任何实体名词(公司、院校、域名、产品)都不得出现在默认文案中;示例描述使用"任意行业报告""某公开文档"这类占位表述。点击建议词仅回填输入框,由用户确认后发送,保留控制感。

### 6. 界面硬编码实体清理遵循"替换为通用判断"

- 头部徽标:删除字面量 "12306" 徽标;保留 Search/Files/Skills/Debug 等通用能力徽标;技能徽标改为从已安装技能动态生成(无技能时不显示)。
- `iconForTool`:改为通用类别判断(网络检索类、文件读写类、终端命令类、其他),移除 "train"/"ticket"/"station" 等领域关键词分支。类别判断基于工具名的通用词根,新增工具无需改代码即可落入合理默认图标。

### 7. 圆角体系整体放大,按信息密度分层

在现有令牌基础上整体上移一档并统一应用:消息气泡、能力卡片、对话框与技能弹窗用大圆角(--radius-lg/xl),底部输入区改为胶囊形态(全圆角外轮廓,ChatGPT/Claude 同款),头像与操作按钮用全圆;调试流、工具参数、JSON 输出等数据密集面板保留小圆角,避免大圆角挤压等宽文本的可读性。应用规则是"元素层级映射到固定令牌",禁止逐处写死像素,保证同类元素圆角一致。

备选方案是全站统一大圆角。它会让技术诊断面板显得松散且占用横向空间,故按密度分层。

### 8. 动效用既有缓动/时长令牌建标准集,统一受"减弱动态效果"约束

样式表已有 `--ease-out`/`--duration*` 令牌与 `prefers-reduced-motion` 媒体查询,在其上沉淀一组标准动效并在规格中固定:

- **入场**:新消息、工具事件与工作动态项以 150-200ms 的淡入 + 轻微上移进入聊天流,只在元素首次插入时播放,轮询重渲染不重复触发。
- **浮层**:对话框、技能弹窗、知识中心以 200ms 淡入 + 缩放(0.96 到 1)出现,遮罩同步淡入;toast 从边缘滑入、定时滑出。
- **微交互**:按钮/卡片悬停时轻微抬升(阴影加深 + 位移 1-2px),主操作按钮悬停加深强调色;会话侧栏折叠继续沿用现有宽度过渡。
- **进行中指示**:流式等待与工具运行中状态使用脉冲/呼吸动画,是全站仅有的循环动画,避免长时间运行的持续消耗。

实现上优先用 `transform`/`opacity` 做动画,不动画 `width`/`height`/`top` 等布局属性,防止聊天流滚动抖动。所有装饰性动效在"减弱动态效果"开启时降级为瞬时切换,状态信息本身不受影响。

### 9. 毛玻璃限定在固定表面,`@supports` 降级保底

毛玻璃(`backdrop-filter: blur` + 半透明填充)只应用于不随滚动变化的少量固定表面:顶部标题栏(改为吸顶)、底部输入区外壳、模态遮罩与浮动控件。主题令牌新增 `--glass-bg`/`--glass-blur`/`--glass-border` 各两套(浅色/暗色),顶栏滚动时对聊天内容产生柔和透视,输入区与遮罩获得层次感。

约束与降级:持久模糊表面不超过 3 处,避免滚动时长驻 GPU 合成开销;对不支持 `backdrop-filter` 的环境用 `@supports not (backdrop-filter: blur(1px))` 降级为半透明实色(必要处加 `-webkit-backdrop-filter` 兼容 Safari);模糊层下保证文本对比度仍满足 AA,避免"玻璃上读不清字"。

备选方案是全站大面积玻璃(卡片、气泡全部毛玻璃)。视觉收益递减且滚动性能风险高,不采纳。

## 风险与权衡

- **毛玻璃性能**:长会话下聊天流持续滚动,模糊表面若蔓延到大面积内容区会造成掉帧;以"仅固定表面、数量上限、@supports 降级"约束,并安排滚动走查。

- **样式回归面广**:令牌化硬编码颜色会触及大量选择器,靠"先补令牌、后批量替换、双主题逐屏走查"控制风险;任务中安排了人工走查节点。
- **单文件继续膨胀**:本次会顺手抽取 `MessageActions`、`Dialog`、`Welcome` 等组件文件,但不做整体文件拆分重构(避免与视觉变更互相放大 diff)。
- **反馈端点未就绪**:反馈功能设计为本地优先,后端端点作为可选任务,不阻塞验收。
- **混合语言文案**:主要控件文案切换为中文可能与部分既有测试断言冲突,任务中要求同步更新测试。
