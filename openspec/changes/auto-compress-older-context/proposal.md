## Why

长对话会逐步消耗模型上下文窗口。当前运行虽然已经能够估算剩余 token，但接近窗口上限时只能继续发送原始历史，容易造成 provider 拒绝、上下文截断或模型丢失早期任务事实。需要在剩余容量降到 20,000 token 时自动压缩最近三个对话以前的历史，同时保留可继续工作的事实信息，尤其是具体数值、文件名和路径。

## What Changes

- 在模型上下文窗口已知且剩余 token 小于或等于 `20,000` 时，自动触发一次历史上下文压缩。
- 将最近三个已完成的用户到助手对话轮次完整保留；其中的原生工具调用、参数和结果继续按现有保护规则发送。
- 使用 LLM 对三个对话以前的全部历史上下文生成摘要，不只保留头尾或抽样；摘要必须保留原文中的具体数值、日期、文件名、路径、标识符、版本、错误码等可验证细节。
- 将摘要作为带来源边界和版本信息的历史上下文投影复用，并保留原始 session 记录作为不可变事实源；压缩不得改写或删除原始消息和工具记录。
- 压缩完成后重新估算上下文容量；如果摘要生成失败或压缩后仍无法满足容量要求，停止本次模型调用并返回明确的上下文压缩错误。
- 发出压缩开始、完成和失败的调试/活动事件，包含压缩前后 token 估算和保留轮次等元数据，不在事件中重复输出完整历史内容。

## Capabilities

### New Capabilities

- `context-compaction`: 在上下文接近模型窗口上限时，对三个最近对话以前的完整历史进行可追踪、保留关键字面细节的 LLM 摘要压缩。

### Modified Capabilities

- None.

## Impact

- 后端上下文组装和容量检查：`backend/agent.py`。
- session 历史的摘要缓存、来源指纹和原始记录保护：`backend/session_store.py`。
- 模型配置读取及压缩阈值/摘要预算配置：`backend/config.py` 或应用配置文件。
- 新增专用摘要模型调用，会增加接近容量阈值时的一次 LLM 请求；摘要失败时不会带着未压缩的高风险上下文继续调用主 agent。
- 新增后端单元测试和运行事件断言；现有最近三轮工具历史恢复行为必须保持不变。
