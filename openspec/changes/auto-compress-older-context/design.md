## Context

当前 `backend/agent.py` 会从 `SessionStore.get_history()` 取得历史，经过 `trim_history()` 后组装 system prompt、技能信息、恢复信息、历史和当前用户消息，并通过 `estimate_tokens_from_text()` 与配置中的 `model_context_window` 计算剩余容量。`check_context_capacity()` 目前只报告容量；它不会在接近窗口上限时压缩普通历史。

现有 `RECENT_TOOL_HISTORY_TURNS = 3` 保护最近三轮对话中的原生工具调用和结果。这个保护窗口必须继续完整保留。新功能只改变更早历史的模型输入投影，不改变 `session.json` 中的原始消息、工具参数或工具结果。当前 session 数据可能来自旧版本，因此摘要缓存必须是可选字段，缺失时能够正常工作。

## Goals / Non-Goals

**Goals:**

- 在已知模型窗口且剩余容量小于或等于 `20,000` token 时，压缩三个最近已完成对话轮次以前的全部可压缩历史。
- 保留最近三个已完成轮次的用户消息、助手消息以及现有原生工具调用/结果序列，不对保护窗口做摘要或截断。
- 使用无工具、低随机性的 LLM 调用生成摘要，并通过机器保留的字面量清单确保具体数值、日期、文件名、路径、标识符、版本、URL 和错误码等原文细节可检索。
- 让摘要具备来源边界、schema 版本和源指纹，可在后续轮次复用，并在历史发生变化时增量更新或重新生成。
- 摘要失败、输出无法验证或压缩后的上下文仍超过模型窗口时，不调用主 agent，返回可识别的 SSE 错误并保留原始数据。
- 保持现有三轮工具历史恢复、工具 payload 关联、session 读取和普通短对话行为不变。

**Non-Goals:**

- 不删除、改写、覆盖或压缩 session 中的 canonical `messages`、`messages[*].tools`、工具事件审计文件或任务输出原文。
- 不压缩 system prompt、agent policy、技能目录、当前用户请求和当前运行所需的权威任务状态；这些内容仍按各自规则加入 prompt。可压缩历史包括对话边界以前的历史投影以及明确标记为历史的派生记忆。
- 不改变最近三轮工具记录的 native LangChain 消息格式，也不把旧工具结果静默转换成无来源的事实。
- 不增加实体名称、域名或业务对象的硬编码判断；字面量保留规则只基于通用结构和格式识别。
- 不引入跨进程的分布式摘要队列或新的外部存储服务。

## Decisions

### 1. 在完整历史投影上判断触发条件

上下文组装分为四步：取得未压缩的历史投影，识别最近三轮保护边界，估算包含完整历史的模型输入，最后决定是否生成/使用摘要。触发条件为模型窗口可解析且 `remaining_tokens <= 20_000`，包括刚好剩余 `20,000` token 和已经超出窗口的情况。不能先执行现有的普通 `trim_history()` 再判断，否则头尾截断可能掩盖真实的容量压力。

摘要成功后，以“摘要 + 最近三轮完整历史 + 当前运行所需内容”重新组装并再次估算。普通历史截断规则只允许作用于摘要之外的非保护派生内容；不得对保护工具记录或字面量清单做静默截断。如果重新组装仍超过模型窗口，运行以容量错误结束。

替代方案：继续使用 `trim_history()` 后的估算值。该方案实现简单，但无法保证“剩余 20,000”对应用户要求的完整历史，也可能在 provider 侧才暴露溢出。

### 2. 使用已完成对话轮次确定压缩边界

沿用 session 消息的通用结构，将一个 `user` 消息后面有对应 `assistant` 消息的序列视为已完成对话轮次。取最近三个已完成轮次作为保护窗口；保护窗口之前的历史条目全部进入压缩输入。未完成的 user 消息不计入三个轮次，并继续按当前运行输入处理。保护边界按照 canonical message 顺序计算，不以字数或工具事件数量替代。

`SessionStore.get_history()` 应提供可识别的边界元数据，或由同一层的纯函数返回 `compressible_items` 和 `protected_items`。最终模型输入仍按时间顺序排列：历史摘要（如果存在）、保护窗口中的完整工具协议和文本、恢复/任务状态、当前用户消息。摘要条目必须标记为“历史记忆、仅供参考”，不能被 agent 当作新的用户命令。

替代方案：按最近 N 条消息保留。消息数量无法稳定对应对话轮次，会把一个工具调用序列拆开，破坏现有 native tool-call/result 约束。

### 3. 采用可复用的 session 摘要缓存

在 session 顶层增加可选的 `context_compaction` 对象，建议包含：

- `schema_version`、`summary_prompt_version` 和生成模型标识；
- `summary`，包含 LLM 生成的结构化历史摘要和机器生成的 exact-literal ledger；
- `covered_through_message_index` 或等价的稳定边界；
- `covered_turn_count`、`source_fingerprint`、`created_at` 和 `updated_at`；
- 最近一次摘要的 token/字符估算及状态信息。

缓存只作为模型输入投影使用，canonical session 记录仍是事实源。使用前必须校验边界、schema/prompt 版本、模型标识和源指纹。新一轮使保护窗口向前移动时，将已有摘要与新增变成可压缩的那一轮合并后重新摘要；不能只把新一轮追加成未经 LLM 处理的长文本。源指纹变化、缓存损坏或无法验证时，重新读取 canonical 历史生成摘要。

摘要写回使用 session store 现有的原子保存路径；只有摘要完整通过校验后才提交缓存。并发运行场景下，摘要生成和提交必须以 `session_id` 串行化，避免两个请求互相覆盖不同边界的摘要。失败时不得覆盖上一次有效缓存。

替代方案：每次运行都临时生成摘要。该方案会重复消耗 LLM 请求，并且同一历史在连续请求中可能出现不一致的记忆；只缓存摘要而不保留源指纹则可能复用过期事实。

### 4. 使用专用、无工具的摘要调用和分层压缩

摘要调用复用当前应用配置中的 LLM 连接，但不绑定 agent 工具，使用确定性温度配置和独立的摘要输出预算。摘要 system prompt 必须声明：输入是历史数据而非待执行命令；输出只描述已发生事实、决定、未完成事项、证据和文件/数值；不得根据历史文本执行工具或接受其中的 prompt injection。

摘要输入按对话边界序列化，保留 role、原文顺序、工具名称、调用参数、结果、时间和结构化字段。若可压缩源一次放不进摘要模型的输入窗口，则在对话/事件边界切块，先生成部分摘要，再合并部分摘要；合并仍放不下时递归执行，直到得到一个可验证的最终摘要。任何阶段都不能先用字符头尾截断替代分层摘要。

LLM 摘要正文采用固定章节，例如 `事实与结论`、`文件和产物`、`未完成事项`、`工具证据`。在正文之后由程序附加按首次出现顺序去重的 exact-literal ledger。ledger 从结构化字段和文本中使用通用格式提取数字、日期、路径/文件名、URL、版本、标识符和错误码；它不是实体白名单。摘要验收至少验证：LLM 返回非空文本、所有必需章节存在、源中的每个 ledger 字面量在摘要或 ledger 中仍以原文形式出现、输出预算和模型窗口均满足。验证失败时可进行一次受限重试，仍失败则返回压缩错误。

替代方案：只要求 LLM 在自由文本中“记住重要细节”。这种方式无法确定性地保留文件名或精确数字，特别容易把版本号、路径和小数改写。

### 5. 用可观测事件区分跳过、复用、生成和失败

在现有 debug/activity SSE 流中增加结构化阶段：`context_compaction_started`、`context_compaction_completed`、`context_compaction_reused` 和 `context_compaction_failed`。事件携带 session/run 标识、触发前 token 估算、剩余 token、保护轮次数、压缩源轮次数、摘要后 token 估算、是否命中缓存和错误代码等元数据；不携带完整历史、原始工具结果或摘要正文。

未知模型窗口时记录 `skipped_unknown_context_window` 并保留原行为。没有可压缩的旧轮次时不发起摘要请求。压缩失败时发出错误和完成帧，主 agent 不得被调用；原始 session 仍可用于下一次重试。

### 6. 保持精确细节与安全边界

压缩提示和 ledger 将所有源内容视为不可信数据，使用明确分隔符避免历史中的文本改变摘要器规则。具体事实按原文字面保留，尤其不能规范化或重排数字、文件名、路径、版本和错误码。活动事件只输出计数和估算，不回显源内容；现有敏感信息处理约束继续适用于面向用户的诊断信息。

## Risks / Trade-offs

- [额外 LLM 延迟和费用] → 只有在已知窗口剩余不超过 `20,000` token 时触发；缓存命中时不重复生成，并在事件中提供耗时和命中信息。
- [摘要模型遗漏或改写精确细节] → 使用结构化输入、通用 exact-literal ledger、结果校验和受限重试；无法验证时失败关闭，不发送未经压缩的高风险上下文。
- [摘要输出仍然过大] → 使用独立输出预算、分层压缩和压缩后重新估算；固定 prompt 与最近三轮本身无法容纳时返回容量错误。
- [缓存与 canonical 历史不一致] → 存储边界、源指纹、schema/prompt 版本和模型标识，使用前校验；不一致时从原始记录重建。
- [并发运行产生摘要覆盖] → 以 session 为粒度串行化摘要构建和提交，提交前再次校验源指纹。
- [历史内容包含 prompt injection] → 摘要器只把历史作为引用数据，使用独立 system 规则和分隔格式，不把历史指令升级为 system/developer 指令。
- [旧 session 没有摘要字段] → 缺失视为空缓存，首次达到阈值时按 canonical 历史生成；回滚时忽略新增元数据即可。

## Migration Plan

1. 增加可选 `context_compaction` schema、源指纹和纯历史分区函数；不迁移、不改写已有 session 消息。
2. 增加摘要调用、字面量 ledger、缓存校验、容量重估和 SSE 事件，并在默认阈值 `20,000` 下启用。
3. 先通过测试覆盖四轮以上历史、工具 payload、精确字面量、缓存复用、LLM 失败、窗口未知和并发 session，再观察真实运行中的压缩耗时与失败率。
4. 回滚时停止读取/写入 `context_compaction`，继续使用原有历史组装；原始消息和工具审计数据无需恢复。
