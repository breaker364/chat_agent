## 为什么

当前终止性异常由少量字符串规则归类，无法基于本次执行证据解释具体问题；同时，非开发人员只能从技术化的调试流和侧栏推断请求进度。需要在不暴露内部推理和原始诊断信息的前提下，提供可信、可读、实时的执行状态与异常说明。

## 变更内容

- 异常终止时，优先由 Agent 根据已脱敏的执行上下文生成具体的用户可读分析；规则化文案仅在分析不可用时兜底。
- 新增 `activity` SSE 事件，用统一结构传递当前工作、已确认事实、判断、下一步和进度。
- 在聊天流中实时展示面向用户的 Agent 工作动态时间线；保留 Debug stream、工具调用分组和任务进度侧栏。
- 为异常分析降级、事件顺序及前端状态收束补充自动化测试。

## 能力

### 新增能力

- `evidence-based-exception-analysis`：基于实际执行上下文生成安全、具体、面向用户的异常说明，并在不可用时安全降级。
- `user-facing-agent-activity`：从可观察的执行事件生成并实时展示用户可读的工作动态和任务进度。

### 已修改能力

无。

## 影响

- 后端：`backend/agent.py` 的事件流、异常处理和 SSE 事件契约。
- 前端：`frontend/src/App.jsx` 的 SSE 解析、请求状态和聊天流组件，以及 `frontend/src/App.css` 的工作动态样式。
- 测试：后端流式/异常恢复测试与前端组件或事件处理测试。
- 不引入新的外部服务；复用当前已配置的 Agent 模型和既有 Debug stream。
