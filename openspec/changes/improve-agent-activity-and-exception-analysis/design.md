## 背景

当前后端在事件流修复次数耗尽后，以 `summarize_exception_for_user` 的少量字符串规则生成错误说明。该说明不利用本次请求的工具、重试和部分结果上下文，因此常常过于泛化。前端已能显示流式文本、工具事件、Debug stream 和任务进度，但这些信息分散且技术化，不能构成面向非开发人员的实时执行叙述。

本变更横跨 `backend/agent.py` 的生命周期事件、`frontend/src/App.jsx` 的 SSE 消费和聊天流组件。必须保持现有事件兼容，并将用户可读信息与技术诊断信息分层。

## 目标与非目标

**目标：**

- 用实际执行证据生成具体、安全、中文的异常分析，并将规则化摘要限定为兜底。
- 用独立、稳定的 `activity` SSE 契约传递用户可读的工作状态、事实、判断、下一步和进度。
- 在当前回复中实时且默认展开地显示工作动态，同时保留既有 Debug stream。
- 为模型降级、事件顺序和前端状态收束提供可自动验证的覆盖。

**非目标：**

- 传输或展示模型隐藏思维链、原始工具参数、密钥或 traceback。
- 更改模型供应商、会话持久化架构或 Debug stream 的技术诊断职责。
- 将每个模型 token 或每条心跳转化为新的用户可见时间线条目。

## 决策

### 1. 使用结构化异常分析并保留本地兜底

终止性异常发生时，后端收集已脱敏的异常摘要、当前工具、近期工具名、错误摘要、修复次数、最近工作动态和部分回答。该上下文交给当前已配置模型，要求其只返回固定字段的 JSON：发生情况、可能原因、完成情况和下一步。后端验证字段非空、长度受限且不包含危险原始信息后，格式化为用户文本。

若模型调用失败、超时、JSON 无效、字段缺失或校验不通过，复用规则化函数生成安全兜底。选择该方案是因为它能针对本次运行解释问题，同时不会让异常处理本身因模型不可用而失效。

备选方案是扩展字符串关键词分支。它稳定但不能覆盖未知失败类型，也违反了本项目避免为具体情况持续堆叠硬编码规则的原则。

### 2. 将用户可读活动与 Debug 事件分为两个 SSE 通道

新增 `activity` 事件，不改变已有 `progress`、`debug`、`tool_call`、`tool_result`、`error` 和 `done` 的含义。`activity` 只携带简洁、经过脱敏和格式化的用户叙述；Debug stream 继续携带可用于诊断的技术细节。

选择独立事件而不是复用 `progress`，因为现有 `progress` 的文本包含工具等待信息，无法表达已确认事实和判断。独立契约也让前端在不破坏工具事件分组的前提下独立聚合和渲染。

### 3. 根据可观察生命周期生成活动，而非暴露推理

请求开始、工具启动、工具完成、修复重试、最终完成和终止失败均生成活动更新。摘要只陈述可观察行为；只有工具结果或异常分析提供了证据时才填充 `evidence` 和 `judgment`。每项活动可附带进度，但进度只反映已知阶段，不伪造总工作量。

心跳复用最近一条工作活动，避免一秒一次的事件造成界面抖动。此设计既满足用户希望实时查看 Agent 工作过程，也避免泄露模型私有推理或制造虚假的“思考步骤”。

### 4. 将时间线置于流式回答内部且默认展开

前端在每次请求开始时初始化活动集合，并在收到 `activity` 时按阶段更新。它以聊天流中的 `Agent 工作动态` 组件显示最新状态、历史条目、进度、事实、判断和下一步。接收到 `done` 时设置完成；接收到 `error` 时标记受阻并显示后端已生成的异常判断。

选择内联时间线而不是仅更新侧栏，是因为用户需要阅读结果时同时看到执行依据。Debug stream 保持现有右侧位置，供开发人员展开查看。

## 风险与取舍

- [模型分析不稳定或变慢] -> 设置严格输入大小、短超时和 JSON 校验；失败立即使用本地兜底，不阻塞终止响应。
- [异常上下文含敏感内容] -> 复用工具载荷脱敏逻辑，仅传递摘要和白名单字段；输出在渲染前再次检查。
- [活动事件过多] -> 对同一活动阶段进行合并，心跳只更新最近工作项。
- [旧前端或客户端不识别新事件] -> 新事件为附加事件，既有事件和最终 `done` 行为保持不变。
- [状态与最终结果不一致] -> 以 `done`/`error` 作为终态权威来源，在前端统一收束当前活动。

## 迁移计划

1. 先发布兼容的后端 `activity` 事件和异常分析降级逻辑。
2. 发布前端时间线渲染，未知事件仍被安全忽略。
3. 用正常请求、工具失败和模型分析不可用三类请求验证生产日志与用户展示。
4. 若出现问题，前端可暂时忽略 `activity` 事件，后端仍保留现有 `progress`、`debug`、`error` 和 `done` 行为；异常说明自动退回规则化兜底。

## 未决问题

无。用户已确认实时展开的对话内时间线；工作动态仅展示可观察执行摘要，不展示隐藏思维链。
