## Why

当前 Agent 的可用上下文主要来自当前 session 历史、上下文压缩摘要、工具结果和 RAG 检索；当用户在新的 session 中继续协作时，长期偏好、反馈、非代码可推导的项目背景和外部参考信息不能被可靠复用。仅依赖 session 历史会造成重复说明，也会让模型在上下文压缩后失去跨会话的稳定工作方式。

需要增加一套受控的持久化 Agent 记忆 MVP：由 LLM 判断哪些对话信息值得长期保存，将其与普通会话记录分离，并在后续请求中以有界、可审计且可遗忘的方式提供给 Agent。

## What Changes

- 新增项目级持久化记忆存储，使用受限目录中的 Markdown 记忆记录和 `MEMORY.md` 索引保存跨 session 信息。
- 在一次对话回合成功持久化后，异步调用受限的 LLM 提取器，从最近的用户和助手消息中生成结构化记忆；提取失败不得影响本次聊天结果。
- 约束记忆为 `user`、`feedback`、`project`、`reference` 四类，并排除代码模式、可从代码或 Git 推导的信息、调试方案、临时任务和原始敏感内容。
- 在每次 Agent 执行前加载有大小上限的记忆索引到动态 system prompt；索引只是导航信息，Agent 仅在相关时通过现有受限读文件能力读取具体记忆，并把记忆视为可能过时的引用数据。
- 提供记忆列表、读取和遗忘的受控接口；删除或更新记忆时同步维护索引，用户可以撤销不应继续保留的信息。
- 新增配置、事件和测试，覆盖禁用开关、提取/注入、去重和更新、路径边界、索引上限、遗忘、异步失败降级以及不泄露内部推理或敏感内容。

## Capabilities

### New Capabilities

- `persistent-agent-memory`: 管理跨 session 的记忆提取、受控存储、索引注入、按需读取、遗忘、安全边界和运行可观测性。

### Modified Capabilities

- None.

## Impact

- 影响后端：`backend/agent.py` 的动态 system prompt 和回合完成生命周期，`backend/main.py` 的会话/API 生命周期，`backend/config.py` 的功能开关与限额，以及新增的记忆存储、提取和注入模块。
- 影响现有能力：与 `SessionStore`、最近三轮原生工具历史、上下文压缩和 Agentic RAG 并存；记忆是独立于 session canonical history 的长期辅助上下文，不得改写原始消息或工具 transcript。
- 影响接口：新增面向当前工作区的记忆查询和遗忘接口；现有聊天接口和 SSE 事件保持兼容，可附加受控的记忆活动元数据。
- 影响持久化数据：新增配置指定的项目级记忆目录、Markdown 记忆文件、`MEMORY.md` 索引和最小运行元数据。MVP 假定单一受信任工作区；启用多用户部署前必须增加所有者命名空间和访问控制。
- 影响测试：新增记忆抽取模型桩、文件/索引原子更新、prompt 注入、异步失败、显式遗忘、并发回合和安全过滤测试；不要求引入新的向量数据库、后台整合任务或模型专用子 Agent。
