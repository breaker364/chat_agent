## ADDED Requirements

### Requirement: Route 节点必须输出受 schema 约束的提议

Route 节点可以使用 LLM 识别请求意图，但其输出 MUST 解析为受限的 `RouteProposal`，至少包含模式、任务类型、研究需求、风险级别、置信度和所需能力；模型输出不得直接指定任意节点、边或未经注册的工具。

#### Scenario: 合法路由提议

- **WHEN** LLM 返回符合 schema、枚举、数量和数值范围约束的路由提议
- **THEN** 系统将其传给确定性裁决器，而不是直接据此跳转图节点

#### Scenario: 非结构化或未知值

- **WHEN** LLM 返回无法解析、未知模式、未知任务类型或未知能力
- **THEN** schema 层拒绝原提议并生成可审计的 invalid_route 原因

### Requirement: 代码策略必须对路由提议做最终裁决

系统 MUST 使用纯代码 `enforce_route` 检查请求完整性、能力注册、知识策略、风险级别、任务/并发/预算上限和确认要求；条件边 MUST 只读取裁决后的结果。

#### Scenario: 模型提议超过资源上限

- **WHEN** 提议的任务数、并行度或预算超过系统配置
- **THEN** 裁决器限制到允许范围或降级到澄清/blocked，不允许模型扩大资源上限

#### Scenario: 请求包含高风险能力

- **WHEN** 提议或任务能力包含需要确认的副作用操作
- **THEN** 裁决结果设置 approval_required，并将流程导向预定义 approval 路径

#### Scenario: 能力未注册

- **WHEN** 路由引用的能力不存在于工具能力注册表
- **THEN** 系统拒绝该能力，保留请求上下文，并返回澄清或 blocked 路由

### Requirement: 路由必须有安全默认值和确定性降级

系统 MUST 为低置信度、路由模型错误、策略冲突和关键输入缺失定义确定性降级；降级路径不得自动获得更高权限或无限增加模型调用。

#### Scenario: 低置信度请求

- **WHEN** 置信度低于配置阈值且无法从上下文确定任务类型
- **THEN** 系统进入 clarification_gate，向调用方返回需要补充的信息

#### Scenario: 路由模型暂时不可用

- **WHEN** 路由 LLM 超时或返回服务错误
- **THEN** 系统使用代码可判定的安全默认路径或返回可重试错误，不直接开放全量工具

### Requirement: 路由、重试和重规划决定必须可审计

系统 MUST 记录原始提议的摘要、schema 错误、代码裁决、降级原因、重试/重规划次数和最终选择；审计记录不得包含不必要的敏感原文。

#### Scenario: 正常路由审计

- **WHEN** 路由裁决成功
- **THEN** 审计事件包含规范化模式、风险、能力集合、策略版本和裁决结果

#### Scenario: 触发重规划

- **WHEN** `assess` 发现当前计划无法完成但允许重规划
- **THEN** 系统记录触发原因和计划版本变化，并保持重规划次数在硬上限内

#### Scenario: 达到重规划上限

- **WHEN** 重规划次数达到上限
- **THEN** 系统停止继续调用 planner，进入 blocked/failed 完成路径并返回可诊断原因
