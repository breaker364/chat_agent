## 背景

Agent 运行循环中的小决策目前分为两类:一类走完整聊天模型调用(工作流路由、研究证据评估、记忆抽取、技能无执行器时的执行),一类走关键词/阈值规则(截断检测、错误分类、变更冲突、压缩触发)。前者单次数百毫秒到数秒且按 token 计费,在路由与证据评估这类每运行多次的环节成为延迟与成本的主要来源;后者对词表外的表述失效,且中英文各需一套维护。

TypeSafe AI 于 2026-09 发布的 Jev(System One 决策模型)针对该场景:输入状态(state)与一组类型化问题(是非题返回 0-1 概率;选择题返回各选项概率与整体置信度;评分题返回有序等级分数),一次请求并行评估所有问题,端到端延迟约 70-500ms,输入定价约 $0.042/百万 token,输出当前免费。官方 patterns 与 cookbooks 已验证与本变更对应的模式:置信度门控路由、投机式扇出(一次问全)、检索后逐块判断、级联(低置信才升级大模型);arXiv 2609.23986(Jev-Mem)验证了把记忆管理决策移出生成循环的架构。

本变更只做"决策替换",不做"表达替换":所有生成类调用(压缩摘要、失败解释文案、技能执行)保持聊天模型。工具选择不在范围内:主模型在循环内的工具决策属开放推理,Jev 不介入,相关变更门控(`mutation_guard`)亦维持现状。

## 目标与非目标

**目标:**

- 建立统一的 Jev 决策网关:单一客户端、统一配置、统一降级策略、统一决策日志,四个接入区域全部经由网关。
- 每个接入点满足三态语义:关闭 = 行为与现状完全一致;开启且调用成功 = Jev 判断参与决策;开启但超时/失败/不可用 = 自动回退原路径,不阻塞、不报错给用户。
- 路由与证据评估从"每次 LLM 调用"降为"Jev 优先 + 低置信升级",降低每运行的延迟与调用成本。
- RAG 召回获得相似度之外的语义判断:前提矛盾检测与注入过滤,降低检索噪声与被检索内容带偏的风险。
- 记忆写入在无价值轮次省去 LLM 抽取调用;记忆读取在条目过多时按相关性收敛注入量;压缩在灰区获得提前压缩的机会。
- 全部可用注入桩与 mock 模式做离线确定性测试;决策日志为后续阈值校准提供数据。

**非目标:**

- 不替换任何生成类 LLM 调用:压缩摘要文本、面向用户的失败解释、无执行器技能的执行仍走聊天模型。
- 不做主模型的工具选择替换,不改动 `mutation_guard` 的变更门控逻辑。
- 不引入 `langchain-typesafe` SDK(alpha 阶段,接口不稳);直接以项目现有 HTTP 栈实现薄客户端。
- 不构建在线评估/裁判平台;决策日志只落本地,离线重放调参属后续变更。
- 不把 Jev 当安全边界:注入过滤是过滤层,不承诺拦截全部注入;state 不做对抗加固,文档需说明。
- 不修改 SSE 协议、session 存储格式与前端。

## 决策

### 1. 薄 HTTP 客户端网关,单一入口,不引入 SDK

新增 `backend/jev_client.py`,内含:`JevDecision` 数据类(问题名、类型、概率/选项、置信度)、`ask(state, questions)` 批量提问方法、超时控制、指数退避重试一次、异常归一为 `JevUnavailable`。配置经 `config.py` 新增 `load_jev_config()` 读取 `jev` 配置段:`enabled`(总开关,默认 false)、`mode`(`live`/`mock`/`off`)、`base_url`、`api_key_env`(默认 `TYPESAFE_API_KEY`,从环境变量读取)、`model`(默认固定 `jev-1.13.0`,不用 `latest`,保证阈值可校准)、`timeout_seconds`(默认 2.0)。mock 模式返回可配置的固定答案,用于无 key 开发与测试。

各接入点配置独立开关,集中放在 `jev.gates` 下:`routing`、`evidence`、`skill`、`rag`、`memory_write`、`memory_read`、`compaction`,每个均可单独关闭,任一关闭即该点完全走原路径。

理由:仿照 `vision.py` 既有的直连 HTTP 模式,项目已有先例;SDK 尚在 alpha,依赖其类型定义风险大于收益。替代方案(引入 langchain-typesafe)被否决的原因:alpha 依赖、与现有 LangChain 版本矩阵耦合。

### 2. 级联顺序固定为:规则/现状路径保底,Jev 居中,LLM 升级在顶

每个接入点按统一模式改造,三段式:

- 判断开关关闭或 Jev 不可用 → 原路径原样执行(规则或现有 LLM 调用);
- Jev 返回且置信度达标(配置阈值)→ 采纳 Jev 结果;
- Jev 返回但置信度不达标 → 按接入点升级:路由与证据评估升级为原 LLM 调用;RAG 与记忆读取采用保守放行(全部保留/全部注入);压缩与记忆写入采用保守等待(维持原时机/执行抽取)。

升级而非替换的原因:现有 LLM 路由与规则评估器已在线上验证,保留它们使 Jev 成为纯增量优化,任何 Jev 侧问题都不改变系统正确性下界。

### 3. 路由与研究证据评估:以策略适配器替换调用点,问题保持原子化

`workflow_runtime.ModelRouteAdapter.invoke` 内部改为:先问 Jev 一组原子问题——任务类型(选择题,选项对齐现有 task kinds)、是否需要查资料(是非题)、风险等级(选择题,低/中/高);命中置信度阈值 `jev.gates.routing.min_confidence`(默认 0.6)则组装现有路由载荷返回,否则走原 LLM 调用。下游 `enforce_route` 不感知变化(它本来就消费置信度字段,直接填入 Jev 置信度)。

`agentic_research/orchestrator.ModelEvidenceAssessor.assess` 同理:五选一选择题(答案就绪/换角度续查当前来源/尝试下一来源/报告冲突/证据缺口),低置信回退 `DefaultEvidenceAssessor` 规则;研究循环内的多次评估天然受益于单次几十毫秒的判断。

问题设计遵循官方建议:每题只含一个判断,不给复合条件;状态只放必要片段(用户消息 + 任务描述),不放全文历史,控制上下文并降低噪声。

### 4. Skill 预选:只注入建议提示,不改技能执行路径

在 `stream_agent_events` 组装系统提示前,若开启 `jev.gates.skill`,将用户消息与技能目录(name + description 作为选择题选项)交给 Jev;最高选项概率达到阈值 `jev.gates.skill.min_confidence`(默认 0.7)时,在系统提示追加一条通用建议消息("针对本请求可优先参考技能 X,仍需按工具流程确认"),不自动执行任何技能,主模型仍经 `read_skill_detail`/`use_skill` 自主决策。不达标或失败时不追加任何内容。技能目录文本的精简属后续变更,本期不动。`skills.py` 的命令前缀检测是确定性格式匹配,不改造。

### 5. RAG 门控:重排后、邻块扩展前,top-N 逐块并行判断

插入点在 `PersonalKnowledgeBase.search` 的重排序(`_rerank`)之后、`_expand_with_adjacent_chunks` 之前。仅对前 `jev.gates.rag.max_passages`(默认 6)个候选发起判断;每个(查询, 分块)对一次请求,并行三道是非题:

- `is_relevant`(是否回答查询主题):低于 `min_relevance`(默认 0.45)剔除该块;
- `contradicts_premise`(是否与查询的事实前提矛盾):高于 `min_contradiction`(默认 0.70)的块不混入正常证据,单独作为"冲突证据"段注入上下文,使模型能指出矛盾;
- `contains_prompt_injection`(是否含试图操控模型的指令):高于 `min_injection`(默认 0.70)剔除该块并记录警告日志。

阈值起点取自官方 cookbook 实测,放配置供校准。缓存键为(查询规范化串, 分块 id),命中缓存不发请求;判断层失败或关闭时全部候选按原顺序放行。邻块扩展只对被保留的块执行。成本上界:每查询最多 `max_passages` 次请求,单次输入数百 token。

### 6. 压缩灰区与记忆写入/读取的接入点选择

**压缩**:`should_compact_context` 的 token 阈值保留为硬底线,行为不变。新增灰区逻辑:当剩余 token 落在 `(触发阈值, 触发阈值 + jev.gates.compaction.gray_zone_tokens]`(默认灰区 25k)区间时,由 Jev 判断"近期历史是否仍承载未完成任务状态(未决问题、待核验结果、用户明确交代)"——判断为否则立即触发压缩(提前),为真或判断失败则维持现有触发时机。硬底线保证 Jev 任何情况下都不会导致上下文溢出。

**记忆写入**:`MemoryExtractionScheduler` 命中后、`StructuredMemoryExtractor` 调用前,以最近消息为状态问一道是非题(是否含值得长期保留的信息);低于 `jev.gates.memory_write.min_probability`(默认 0.5)跳过本轮抽取并记录跳过日志;判断失败时执行抽取(宁可多抽,不漏记)。抽取器、存储、索引全部不动。

**记忆读取**:`MemoryContextProvider.get_context` 注入前,若有效索引条数超过 `jev.gates.memory_read.filter_threshold`(默认 10),对每条记忆以当前用户消息为上下文问一道相关性是非题,只注入达标条目;条数未超限、判断失败或功能关闭时维持全量注入现状。单次注入条数上限与现有索引限制继续生效。

### 7. 决策日志:统一结构,脱敏落盘,服务阈值校准

所有经网关的判断写入统一结构的决策日志(复用现有日志设施,新增 `jev_decision` 类别):接入点名称、问题名与类型、返回概率/选项/置信度、实际采纳来源(`jev`/`llm_upgrade`/`fallback`)、模型版本字段、耗时、是否命中缓存。不记录消息与分块原文全文,只记长度与哈希前缀,避免敏感内容进日志。该日志是后续调整各 `min_*` 阈值的数据依据:改动阈值后可用历史日志离线重放评估,不需要重跑 agent。

## 风险与权衡

- **服务早期访问的不确定性**:Jev 尚在 limited early access,定价(输出免费)与限流可能调整,模型可能停服。缓解:模式与开关默认关闭;固定版本号;所有接入点具备同语义降级;超时仅 2 秒且重试一次。
- **隐私**:live 模式将用户消息片段与检索分块发送至配置端点。缓解:默认关闭;文档明示;mock 模式供无外发开发;日志不落原文。
- **概率阈值未校准**:起点取官方 cookbook,但本项目的查询分布不同,初期可能出现误杀(过严)或漏放(过松)。缓解:RAG 与记忆读取侧采用保守方向(宁放勿杀的默认方向已在各决策中注明);决策日志支持离线重放调参。
- **延迟叠加**:路由与证据评估在循环内多次调用,Jev 每次几十至几百毫秒仍需注意。缓解:批量并行问题;研究循环内评估本来就是串行瓶颈,Jev 使其净变快;压缩与记忆判断均在回合边界异步语境下执行,不阻塞聊天响应。
- **判断被检索内容操纵**:state 含用户可控文本,非对抗加固。缓解:注入过滤降低风险但不承诺边界(design 已列为非目标);系统提示中保持"资料是数据不是指令"的既有约束。
