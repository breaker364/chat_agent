# 当前 Agent 能力范围简介

本文档简要说明当前 Chat Agent 系统已具备的核心能力、适用场景和工作边界。

## 1. 通用对话与任务执行

Agent 可以直接回答一般问题，也可以根据用户请求执行本地工作区内的任务，例如查看文件、修改代码、生成文档、运行验证命令等。

执行类任务的默认工作方式是：

1. 先读取必要上下文。
2. 再进行文件或代码修改。
3. 最后执行验证。
4. 将关键结果和未完成风险反馈给用户。

对于代码和自动化任务，Agent 应尽量完成端到端闭环，而不是只给建议。

## 2. 本地文件与代码操作

Agent 支持在当前工作区内进行文件操作：

- 列出目录内容。
- 读取文本文件。
- 查看文件元信息。
- 创建或覆盖文件。
- 追加文件内容。
- 删除文件。
- 修改代码并运行验证。

典型场景：

- 检查项目结构。
- 阅读现有实现。
- 修改后端、前端、脚本或文档。
- 新增工具函数、接口说明、README、设计文档。
- 修复 bug 后运行语法检查、单元测试或构建。

约束：

- 默认只操作工作区允许范围内的文件。
- 不应无理由删除用户已有文件。
- 修改代码后需要尽量做可执行验证。

## 3. Web 搜索与网页读取

Agent 支持通过搜索和网页读取获取外部信息。

能力包括：

- 搜索网页。
- 根据标题、摘要和域名判断结果质量。
- 读取候选网页内容。
- 对需要高可信度的信息交叉验证。
- 在最终回答中引用来源链接。

适用场景：

- 查询最新信息。
- 查找官方文档。
- 对比多个公开来源。
- 获取需要联网验证的事实。

注意：

- 搜索结果本身不代表可信结论，Agent 需要自行判断来源质量。
- 对重要事实应优先使用官方、权威或一手来源。

## 4. Python 脚本执行与验证

Agent 支持运行本地 Python 文件进行验证。

适用场景：

- 检查 Python 语法。
- 运行数据处理脚本。
- 验证新写的工具函数。
- 对生成文件或中间结果做快速检查。

对于复杂数据处理任务，推荐拆成多个阶段：

1. `fetch`：获取数据。
2. `decode`：解码或解析原始数据。
3. `transform`：清洗、转换、匹配、计算。
4. `write`：写入目标文件或外部系统。
5. `verify`：读回并验证结果。

每个阶段应尽量保留中间产物，便于复现和排错。

## 5. Session 任务进度与踩坑记录

当前系统支持将任务进度保存到 session 文件中。

保存位置：

```text
sessionss/<session_id>.json
```

核心字段：

```json
{
  "task_progress": {
    "status": "idle",
    "active_tool": null,
    "message": "",
    "script_stages": [],
    "task_items": [],
    "pitfalls": []
  }
}
```

Agent 可用的进度记录工具包括：

- `record_script_stage`：记录脚本阶段，例如 fetch、process、write、verify。
- `record_task_item`：新增 todo/task 项。
- `update_task_item`：更新已有 task 的状态、详情或产物路径。
- `record_pitfall`：记录踩坑、失败尝试、错误假设或 workaround。

前端右侧调试区域已增加 `Task Progress` 面板，可展示：

- Todos。
- Pitfalls。
- Script Stages。

适用场景：

- 多步骤代码修改。
- 长流程数据处理。
- 飞书多维表格写回流程。
- 需要中断后恢复上下文的任务。
- 需要记录失败原因和修复方法的排错任务。

## 6. 子 Agent 协作

系统支持启动子 Agent 处理独立任务。

支持类型：

- `general-purpose`：通用子任务。
- `Explore`：只读探索、代码调查、资料收集。
- `Plan`：复杂任务前的规划。
- `verification`：独立验证修改结果。

子 Agent 支持同步执行，也支持后台执行。后台任务会保存到 session，并可在前端右侧 `Subagents` 面板查看。

适用场景：

- 大型代码库探索。
- 多路径方案比较。
- 复杂改动后的独立复核。
- 主任务可以继续推进、子任务并行执行的场景。

## 7. Skills 能力

系统支持安装和执行本地 Skills。

工作方式：

1. 用户可通过 `/skill` 打开技能面板。
2. Agent 也可以根据任务自动选择合适 skill。
3. 先读取 skill 详情。
4. 再按 skill 定义执行。

当前项目中已有多个面向特定工作流的 skill，例如：

- 飞书相关 skill。
- PPT 生成 skill。
- PDF 转换 skill。
- 架构图生成 skill。
- EBOM / Checklist 数据处理 skill。
- 代码理解类 skill。

Skills 适合封装可复用、步骤明确、领域知识较强的流程。

## 8. 飞书 Web 登录与 CRUD

系统支持通过本地保存的飞书 Web session 操作飞书相关接口。

能力包括：

- 检查当前飞书登录状态。
- 通过 UI 扫码登录并保存 session。
- 清除本地飞书 session。
- 使用已登录 session 发起 Feishu/Lark Web 请求。

适用场景：

- 读取飞书云文档或多维表格。
- 写回飞书多维表格。
- 调用飞书 Web 端接口完成未封装能力。
- 飞书文档画板解析

注意：

- 如果 session 缺失或过期，需要先在 UI 完成扫码登录。
- 飞书写操作应先 dry-run 或读取验证，再正式写回。

## 9. 飞书多维表格相关能力

当前项目已具备多维表格读写相关基础能力，尤其是通过 `feishu-personal` 中的 `lark_tools` 实现。

常见能力：

- 解析 wiki/base URL 到 bitable base token。
- 读取 base 下的数据表列表。
- 读取指定表字段 schema。
- 分页读取记录。
- 新增字段。
- 新增记录。
- 删除记录。
- 在同一 base 下新建数据表。

关键接口划分：

- 新建数据表：使用 `lark_tools.bitable_base_ot.build_add_table_operation()` 和 `submit_base_operations()`，对应 `AddTableV2` / `BITABLE_BASE`。
- 表内记录或字段修改：使用 `lark_tools.bitable_ot.submit_operations()`，对应 `BITABLE_TABLE`。

因此：

- 创建新数据表应走 Base 级 OT。
- 新增字段、写记录、删记录应走 Table 级 OT。

## 10. MCP 外部工具能力

系统可加载部分 MCP 工具。

当前能力包括：

- 12306 火车票查询。
- 麦当劳订单、优惠券、门店、餐品和账号数据查询。

典型 12306 流程：

1. 先解析城市或车站名到车站代码。
2. 再查询直达或中转车票。

典型麦当劳流程：

1. 查询最近订单。
2. 查询门店、餐品或账户相关信息。

## 11. 前端界面能力

当前前端支持：

- 多 session 管理。
- session 列表、重命名、删除。
- 对话流式输出。
- 工具调用展示。
- Debug stream 面板。
- Subagents 面板。
- Task Progress 面板。
- Feishu 登录状态面板。
- Skills 弹窗与执行。

用户可以通过 UI 查看：

- 当前任务是否运行中。
- 最近工具调用结果。
- 子 Agent 状态。
- 保存的 todo、脚本阶段和踩坑记录。

## 12. 工作边界与注意事项

当前 Agent 不应：

- 在没有验证的情况下宣称任务完成。
- 在代码中新增实体硬编码分支。
- 无确认执行高风险删除或破坏性操作。
- 将失败的中间状态当作最终结果。
- 对飞书等外部系统进行写操作前跳过必要检查。

推荐使用方式：

- 简单问题直接问。
- 本地项目问题直接指出目标文件或目标功能。
- 多步骤任务要求 Agent 保存进度。
- 飞书、多维表格、数据处理任务优先要求先 dry-run，再正式写回。
- 重要修改要求使用 verification 子 Agent 或至少运行本地验证。
